FSR-VLN: Fast and Slow Reasoning for Vision-Language Navigation (arXiv 2025)

Created on June 11, 2026

2026   ·   vln   navigation   mapping   foundation-model   ·   paper-review

항목 내용
저자 Xiaolin Zhou, Tingyang Xiao, Liu Liu, Yucheng Wang, Maiyue Chen, Xinrui Meng, Xinjie Wang, Wei Feng, Wei Sui, Zhizhong Su (Horizon Robotics / D-Robotics)
발표 arXiv 2509.13733 (v3 2025-11-25), cs.RO — 학회 채택 여부 확인되지 않음
링크 arXiv · Project (fsr-vln 폴더, 프로젝트 페이지만 있고 실행 코드 미공개)

한 줄 요약

FSR-VLN은 floor → room → view → object 4계층의 계층적 멀티모달 씬그래프(HMSG)를 먼저 구축하고, 그 위에서 CLIP 기반 빠른 매칭(직관)으로 후보 방·시점·물체를 고른 뒤, 빠른 매칭이 미심쩍을 때만 VLM(GPT-4o) 기반 느린 추론(검증·정제)을 호출하는 “빠른-느린(dual-process)” 객체 탐색 시스템이다. Unitree-G1 휴머노이드가 수집한 실세계 장거리 사무실 환경 87개 지시에서 SR 92%를 평균 응답시간 5.5초에 달성해, 매번 VLM을 돌리는 MobilityVLA류 대비 응답시간을 82% 줄였다고 보고한다.

연구 계보와 동향

  • 기하·시맨틱 맵 기반 ObjNav. CLIP, OWL-ViT, LSeg 같은 비전 파운데이션 모델의 특징을 voxel/point cloud에 임베딩하는 VLMap, OK-Robot, OVL-MAP 계열. 기하 일관성과 open-vocabulary 질의는 가능하지만 재구성 노이즈·odometry drift에 취약하고 LLM/VLM과 직접 상호작용하기 어렵다.
  • 3D 씬그래프. ConceptGraphs, HOVSG, DOVSG, OpenIN이 floor/room/object를 노드로 추상화해 LLM 인터페이스를 제공한다. 그러나 “object A in region B on floor C” 같은 경직된 지시 포맷과 CLIP 유사도 검색에 의존해 VLM 추론을 충분히 활용하지 못한다.
  • 이미지 토폴로지 그래프. MobilityVLA(long-context VLM으로 goal frame 검색), Uni-NaVid, ReMEmbR, MapGPT, Astra, RoboHop, TANGO. 원본 이미지를 보존해 VLM과 잘 맞지만 3D 구조가 없고 video captioning에 의존해 긴 시퀀스에서 비효율적이며 시맨틱-기하 불일치가 생긴다.
  • 이 논문의 전환. 두 계열(계층적 씬그래프 + 이미지 토폴로지)을 하나로 합친 HMSG를 제안한다. 핵심은 전통적 3계층 사이에 view 노드 층을 추가해 VLM 추론용 이미지 단위 표현을 명시적으로 보유한 것이다. 여기에 Kahneman의 시스템 1/2식 fast(CLIP) → slow(VLM) 조건부 호출을 얹어 정확도와 지연을 동시에 잡으려 한다.
  • 동시대. osmAG-LLM(HM3D-SEM 비교 대상), JanusVLN, DreamNav 등 VLM 기반 VLN이 쏟아지는 흐름이다. 2025-09 최초 공개라 후속 인용 영향은 아직 확인되지 않는다.

문제와 동기

기존 VLN은 장거리 공간 추론이 약하고, 특히 긴 복도와 여러 방이 있는 실내에서 성공률이 낮고 추론 지연이 크다. 저자들이 지목하는 근본 병목은 환경 지식을 인코딩·조직·검색하는 지속적 장거리 공간 메모리의 부재다. 기하 맵과 3D 씬그래프는 기하 일관성은 있으나 사전 추출 특징에 의존하고 VLM과의 직접 상호작용이 약하다. 반대로 이미지 토폴로지는 VLM 친화적이지만 3D 구조가 없고 긴 영상 캡셔닝이 비효율적이다. 또한 VLM을 매 질의마다 전체 영상에 돌리면 정확하지만 느리다(MobilityVLA 약 30초). “항상 무거운 추론을 쓰는 것은 낭비”라는 것이 동기다.

HMSG (Hierarchical Multi-modal Scene Graph)

4계층 노드이며 각 노드는 기하·시맨틱·토폴로지 멀티모달 특징을 가진다.

노드 기하 시맨틱 연결
Floor min/max 높이, PLY point cloud id/name 자식 room 리스트
Room 2D 폴리곤 경계, point cloud name + CLIP 임베딩 연결된 view·object
Object 3D bounding box, point cloud CLIP 임베딩 부모 room, 보이는 view
View (신규) camera pose CLIP 임베딩 + VLM(GPT-4o) 생성 텍스트 설명 보이는 object(visibility), view 간 무방향 엣지 = 상대 pose

전통 씬그래프는 “방에 의자가 있다”까지만 알고 CLIP 매칭에만 의존해 시각·공간 이해가 빈약하다. view 층을 끼우면 “이 시점에서 이 물체가 이렇게 보인다”를 VLM이 직접 읽고 추론할 수 있어, 이미지 단위 내비게이션과 물체 위치 추정을 동시에 강화한다. view 노드 사이 상대 pose 엣지는 전역 경로계획에 쓰인다.

HMSG 구축

  • SLAM은 FAST-LIVO2(LiDAR-관성-비전 odometry)로 RGBD와 pose를 추출하고, HOVSG 방식으로 instance-level open-vocabulary 맵을 만든다. object와 view는 top-down 맵의 기하 겹침으로 방에 귀속된다.
  • floor·room을 순차 추가하며 CLIP 특징을 부여한다. HOVSG와 달리 GPT-4o로 이미지 view에서 room 이름을 추론한다.
  • 각 view에 CLIP 임베딩 + VLM 캡션 + camera pose를 저장하고, 보이는 object를 view에 엣지로 연결한다.
  • 각 object에 대해 보이는 view들의 평균 depth를 계산해 가장 가까운(min depth) view를 “best view(대표 시점)”로 지정한다. 이것이 뒤의 slow reasoning 검증 기준이 된다.

Fast-to-Slow 추론

  1. LLM 기반 지시 이해. 공간 명시적 지시(“사무실의 파란 원통 스툴로 가”)는 LLM이 계층 개념 파서로 floor/region/object로 분해해 씬그래프 노드에 매핑한다. 비공간 지시(“피곤해, 어디서 쉬지?”, “목말라”)는 LLM이 목표 추론 에이전트로 사용자 의도에서 가장 관련 있는 물체·영역을 추론한다.
  2. Fast Matching (CLIP). 방 이름이 있으면 먼저 방을 매칭하고 그 안에서 view·object를 매칭한다. 질의 텍스트와 view 임베딩의 CLIP 유사도로 goal view를, 질의 텍스트와 object 임베딩의 유사도로 후보 타겟을 고른다. 빠르지만 CLIP 한계로 오답이 가능하다.
  3. Slow Reasoning (GPT-4o, 조건부 호출).
    • 검증: fast로 고른 object의 best view를 GPT-4o에 보여주고 “이 view에 이 물체가 있는가”를 묻는다. HMSG상 object는 자기 best view에 반드시 나타나므로, GPT-4o가 “없다”고 하면 그 매칭은 신뢰 불가로 판정한다.
    • view 재선택: 잘못이면 LLM이 미매칭 view들의 텍스트 설명으로 가장 의미적으로 일관된 이미지를 view-1로 고르고, fast-matched view와 view-1을 VLM 추론으로 비교해 최종 goal image를 결정한다.
    • object 재매칭: goal image가 정해지면 그 image의 object 리스트를 순회하며 질의-object CLIP 유사도를 재계산해 goal object를 갱신한다.

비유하면 빠른 직감으로 답을 떠올린 뒤, 그 직감이 미심쩍을 때만 사진을 다시 꼼꼼히 들여다보며 검산하는 사람이다.

실험과 결과

설정. 하드웨어는 Unitree-G1 휴머노이드 + Intel RealSense D455 RGBD + Livox Mid360 LiDAR. 음성 인식(FunASR + VAD), LLM 타겟 추론, HMSG, 경로계획, 전신 제어까지 통합했으며 추론은 클라우드, 로봇은 데이터 수집·제어를 담당한다. 데이터셋은 휴머노이드가 수집한 실세계 장거리 사무실 4개(긴 복도 + 여러 방)와 HM3D-SEM 8개 장면. 지시는 MobilityVLA 셋업을 따라 크라우드소싱한 87개를 4종으로 나눴다: RF(Reasoning-Free), RR(Reasoning-Required), SO(Small Objects), ST(Spatial Target, 방 타입으로 장거리 메모리 시험). 지표는 SR과 RSR top-n@k(top-n 예측 중 하나가 GT로부터 k m 이내). 베이스라인은 OK-Robot, HOVSG, MobilityVLA(비공개라 GPT-4o로 자체 구현, CLIP top-50 프레임 선별 후 추론), HM3D-SEM에서는 HOVSG·osmAG-LLM.

실세계 결과 (87개 지시).

방법 SR 응답시간
OK-Robot 0.609 0.2s
HOVSG 0.517 0.2s
MobilityVLA (재구현) 0.345 ~30s
FSR-VLN 0.920 5.5s (fast만 1.5s)
  1. SR 92% (80/87). MobilityVLA·OK-Robot·HOVSG 대비 각각 +167%, +51%, +77% 상대 개선. FSR-VLN은 “정답 방 안에 있어야 성공”이라는 더 엄격한 기준을 적용했다.
  2. 응답시간 5.5초. slow를 fast 실패 시에만 호출하고, 전체 시퀀스가 아닌 후보 view에만 VLM을 적용한 덕분에 MobilityVLA 대비 82% 단축.
  3. 장거리 강건성. RSR@Top1이 4-5m 임계에서 96.6%(84/87)로 전 거리에서 최고. MobilityVLA는 단거리(1-2m)에서는 최저지만 3-5m에서는 FSR-VLN 다음 2위로 시퀀스 추론력을 보인다.

HM3D-SEM (RSR@Top1 1/2/3m). FSR-VLN 0.87/0.88/0.88 vs HOVSG 0.52/0.64/0.70, osmAG-LLM 0.28/0.50/0.69. osmAG-LLM은 시각 CLIP 특징을 버리고 XML 텍스트만 써서 Top1이 크게 낮다.

Ablation (RSR@Top1, 1m). ST·NR 모두 없음 0.724 → ST 있음 0.816(방 정보로 검색을 해당 방에 한정) → ST + NR 0.920(VLM 검증·정제 추가). 방 단위 가이드와 느린 추론이 둘 다 기여하며, NR은 1.5초 → 5.5초의 비용으로 RSR을 끌어올린다.

읽을 때 주의할 점.

  • MobilityVLA가 비공개라 저자가 GPT-4o로 재구현했다. 원논문 대비 약화되었을 가능성이 있어 167% 우위는 과대평가 위험이 있다. OK-Robot/MobilityVLA는 방 정보가 없어 ST 지시를 해석하지 못하는데, “다른 방의 동종 객체도 성공으로 인정”해 보정했다지만 비교 비대칭이 남는다.
  • 실세계 평가는 자체 수집 4개 방, 87개 지시로 규모가 작고 공개 벤치마크가 아니라 외부 검증이 어렵다.
  • 지표가 RSR(검색 성공률) 중심이다. 실제 주행 성공이 아니라 “타겟 좌표 검색”이 맞았는지를 주로 재며, 경로계획·제어·실제 도달 성공률(SPL 등)의 정량 보고는 없다. “navigation” 성공이라기보다 “goal retrieval” 성공에 가깝다.
  • view 층 자체 제거, GPT-4o vs 오픈 VLM, slow reasoning 호출 빈도·실패율 통계 같은 ablation이 없다. “82% 단축”의 분모인 slow 호출 비율은 데이터셋 의존적일 수 있다. 정성 예시는 한 방의 성공 사례만 있고 실패 모드 분석이 없다.

결론과 의의

계층 씬그래프(기하·장거리)와 이미지 토폴로지(VLM 친화)를 view 노드로 봉합한 HMSG는 VLM 시대 VLN 맵 설계의 실용적 청사진이다. “항상 VLM”이 아니라 fast intuition이 실패할 때만 slow VLM을 부르는 조건부 캐스케이드는 실세계 휴머노이드의 지연 예산 문제에 직접적인 해법이며, 비용·지연에 민감한 온디바이스/클라우드 하이브리드 배치에 시사점을 준다. view 층 + 조건부 fast/slow는 실용적이고 합리적인 엔지니어링 통합으로 보이며 지연-정확도 트레이드오프 개선은 설득력이 있다. 다만 “SOTA”와 정량 우위 폭은 자체 벤치마크·재구현 베이스라인이라는 한계 위에서 읽어야 한다.

로봇 실무 관점에서 정리하면 다음과 같다.

  • 어디에 쓸 수 있는가. 실내 다층 건물 모바일 로봇 자율주행에서 “층 → 방 → 시점 → 물체” 계층 지도는 사무실·병원처럼 방 구조가 명확한 환경에 잘 맞는다. 특히 사용자가 “탕비실 정수기”처럼 방 이름을 말하는 운용 시나리오에서 ST 가이드만으로도 RSR이 0.724 → 0.816으로 오른다는 ablation은 곧바로 적용할 가치가 있다.
  • 지연 예산 설계. 오픈 VLM이든 API VLM이든 매 질의마다 부르지 않고, 저비용 임베딩 매칭의 신뢰도가 낮을 때만 호출하는 캐스케이드 구조는 어떤 시스템에도 이식 가능한 패턴이다.
  • 한계. HMSG 구축이 느려 실시간 매핑이 불가하고(저자 인정), 정적 환경을 가정하므로 가구가 옮겨지는 환경은 못 다룬다. slow reasoning이 GPT-4o의 시각 판단에 의존하므로 폐색·유사 객체·조명에서의 오판 분석이 없고, 오픈 VLM으로의 대체 가능성과 성능 격차도 불명이다.
  • 재현 난이도는 상이다. GitHub의 fsr-vln 폴더는 프로젝트 페이지(index.html + static)만 있고 실행 코드·학습 스크립트가 없으며(2026-06 확인), 리포 전체에 LICENSE 파일이 없어 사용 권리가 불확실하다. 체크포인트·87개 지시·4개 방 데이터셋도 미공개다. 의존 스택(FAST-LIVO2, HOVSG, GPT-4o API, FunASR, Unitree-G1 + D455 + Mid360)도 무겁다. 다만 HOVSG(공개) 위에 view 층과 GPT-4o 검증 로직을 직접 구현하면 알고리즘 자체는 재현 가능하다(Algorithm 1과 추론 흐름이 비교적 명확). 동일 벤치마크가 없어 수치 일치 검증은 불가하다.
